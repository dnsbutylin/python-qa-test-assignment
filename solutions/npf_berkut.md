## 1. Что не обязательно для теста

Речь про тест-кейс как описание проверки, а не про протокол прогона.

Не обязательны:

- Фамилия тестировщика, создавшего тест. Это учётная пометка, на смысл проверки она не влияет.
- Полученные результаты. Это факт конкретного прогона. В самом тесте их заранее быть не должно: иначе ожидаемое подменяется тем, что однажды увиделось.
- Дата проведения теста. Тоже атрибут прогона, а не описания.
- Постусловия. Они полезны, чтобы вернуть стенд в исходное состояние, но вердикт «прошёл / не прошёл» считается по ожидаемому результату. Для автотеста очистку обычно забирает фикстура, а не текст кейса.

Обязательны:

- Название. Без него набор нельзя ни разобрать, ни сослаться на него в дефекте.
- Шаги с нумерацией. По ним проверку повторяет другой человек.
- Ожидаемый результат. Без него тест не самопроверяющийся.
- Предусловия. Для формы и для базы шаги без исходного состояния невоспроизводимы. Это не украшение, а часть сценария.

## 2. Тесты формы «Добавить канал доставки»

По макету жирным выделены «Способ доставки», «Приоритет» и «Схема доставки». «Продолжительность» и флаг подтверждения выглядят необязательными. Ниже это принятое допущение: если на боевом макете жирным отмечена ещё и продолжительность, кейсы N5–N8 остаются, а пустая продолжительность переезжает в негативные.

Общие допущения, чтобы ожидаемый результат был однозначным:

- приоритет — целое число, ноль допустим, отрицательные нет; чем больше число, тем выше приоритет;
- продолжительность, если заполнена, — целое число часов от 0 до 24 включительно; пустое поле сохраняется как NULL;
- способ доставки выбирается только из списка: `sms`, `автопрозвонщик`;
- схема доставки выбирается только из справочника, который ведёт администратор;
- пара «способ + схема» у одного шаблона уникальна;
- повторный щелчок по Ok не создаёт вторую строку;
- Отмена и крестик закрывают окно и ничего не пишут в БД.

Общее предусловие, если у кейса не сказано иное: открыто окно «Добавить канал доставки» для существующего шаблона, у пользователя есть право на изменение, в справочнике есть хотя бы одна схема.

## 4. Students и Results

Ошибочные запросы — первый и третий.

1. `SELECT * FROM Students WHERE Mark > 5;`
   В `Students` есть только `ID` и `Name`. Столбца `Mark` там нет, он лежит в `Results`. На Oracle это `ORA-00904: "MARK": invalid identifier`. Запрос не выполнится.

2. `SELECT S.ID FROM Students S;`
   Запрос корректный. Вернёт 123, 124, 125.

3. `SELECT * FROM Students GROUP BY Name;`
   В выборке есть `ID`, а в `GROUP BY` только `Name`. `ID` не в группе и не в агрегате. На Oracle это `ORA-00979: not a GROUP BY expression`. Запрос не выполнится.

4. `SELECT * FROM Students WHERE NOT EXISTS (SELECT * FROM Results WHERE ID = 2);`
   Синтаксически верен и выполняется. Подзапрос не связан со строкой `Students`, а `ID = 2` в `Results` нет (там 123 и 124). Пустой подзапрос делает `NOT EXISTS` истинным для каждой строки, поэтому вернутся все три студента. Это странная логика, но не ошибка разбора и не ошибка исполнения. Вопрос просит именно такие ошибки, поэтому четвёртый пункт в ответ не берётся.

Итог: ошибочны запросы 1 и 3.

## 5. Самые новые книги

Подходит второй запрос.

```sql
SELECT DISTINCT Title
FROM Book
WHERE Pub_Year = (SELECT MAX(Pub_Year) FROM Book);
```

Максимальный год в данных — 2003. Результат: «Французский язык» и «Как это делалось в Одессе».

Почему остальные нет:

- `WHERE Pub_Year = MAX(Pub_Year)` неверен: агрегат нельзя писать в `WHERE`. На Oracle это `ORA-00934: group function is not allowed here`.
- `WHERE Pub_Year >= Pub_Year` истинно для каждой строки и вернёт все четыре названия, а не только самые новые.
- Вариант «ни один не подходит» неверен, потому что запрос с подзапросом задачу решает.

## 7. PL/SQL

### А. Ошибка в динамическом SQL

Строка обрывается раньше времени. Кавычка перед `SMS` закрывает литерал, `SMS` остаётся голым идентификатором, дальше ещё одна пара кавычек.

Компилируется так:

```sql
execute immediate 'select serv_type_id from service where serv_name = 'SMS'' into v_serv_type_id;
```

Нужно удвоить кавычки внутри строки:

```sql
execute immediate
  'select serv_type_id from service where serv_name = ''SMS'''
  into v_serv_type_id;
```

Надёжнее не склеивать литерал, а передать значение через `USING`:

```sql
execute immediate
  'select serv_type_id from service where serv_name = :serv_name'
  into v_serv_type_id
  using 'SMS';
```

Сам `INTO` у `EXECUTE IMMEDIATE` стоит на месте. Ошибка именно в кавычках.

### Б. Чему равно `v_value`

`v_value` равно **250**.

`get_new_value(250)` попадает в первую ветку: `250 > 100`, поэтому `v_new_value := i_old_value`. Ветка `i_old_value > 200` недостижима: любое число больше 200 уже больше 100 и из функции выходит раньше. До умножения на 2 и до обнуления выполнение не доходит.

Если бы пороги стояли в обратном порядке, 250 ушло бы в удвоение и напечаталось бы 500. При текущем порядке печатается 250.

### В. Ошибки работы с коллекцией

Ошибки две.

1. Вложенная таблица не инициализирована. `v_items` после объявления равен `NULL`, вызов `v_items.extend` даёт `ORA-06531: Reference to uninitialized collection`. Перед `extend` нужно `v_items := t_item_tbl();`.

2. У локального `RECORD` нет конструктора, как у объектного типа. Выражение `t_item_rec(1, 'item1')` для записи, объявленной в блоке, в классическом PL/SQL не собирается (`PLS-00382` / нет такого конструктора). Поля пишутся отдельно. Позиционные qualified expressions для записей появились в Oracle 18c, на схеме биллинга этого поколения на них рассчитывать не стоит. До присваивания выполнение всё равно не дойдёт: сначала упадёт пункт 1.

Индекс `v_items(v_items.count)` сам по себе верный: после `extend` у вложенной таблицы один элемент с индексом 1. Ошибок в типе `TABLE OF` запись тоже нет, такая коллекция в PL/SQL допустима.

Рабочий вариант:

```sql
declare
  type t_item_rec is record (
    id   integer,
    name varchar2(255)
  );
  type t_item_tbl is table of t_item_rec;
  v_items t_item_tbl;
begin
  v_items := t_item_tbl();
  v_items.extend;
  v_items(v_items.count).id := 1;
  v_items(v_items.count).name := 'item1';
end;
```
